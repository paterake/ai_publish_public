In traditional development: requirements → design → **code**.

Code is the deliverable. Artifacts describe it. When they conflict, the code wins.

In AI-assisted development, this inverts.

Code is now cheap — an AI generates it from direction on demand. What isn't cheap is the direction itself: the governance rules, implementation definitions, constraints, and decisions encoded in structured markdown artifacts.

Those artifacts are the deliverable now. Code is the by-product.

Which changes what "losing a file" means.

In the old model, losing a design doc is unfortunate. You can re-derive it from the code.

In the AI model, losing an artifact is a requirement disappearing. The code it governed keeps running — without the constraint that defined it. Nothing breaks visibly. The requirement simply stops existing.

This is why coverage, mapping, and explicit exclusion aren't optional in AI-assisted workflows. They're governance for the primary artifact.

Lesson: protect the artifact first. The AI will regenerate the code. It cannot regenerate what you lost.
