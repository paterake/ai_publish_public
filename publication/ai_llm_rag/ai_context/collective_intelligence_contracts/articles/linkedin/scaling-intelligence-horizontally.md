Adding a second AI coding assistant felt like a productivity upgrade.

Adding a third felt like a reliability downgrade.

Nothing “blew up”. It was worse than that. The system started to erode quietly:

- one assistant applied a constraint the next assistant never saw
- a third “tidied” a detail that looked redundant locally but was load-bearing globally
- every new session spent time re-triaging decisions we’d already paid for

That’s when it clicked: scaling AI-assisted work isn’t primarily a model problem. It’s a coordination problem.

If you want results to improve as you add assistants (or just add more sessions), you need three things to be shared and durable:

1) Alignment: what we’re doing, what we’re not doing, and what “done” means
2) Continuity: a system of record that survives short sessions, tool switches, and restarts
3) Enforcement: guardrails that make the important constraints hard to forget

More agents increases capacity. It doesn’t automatically create compounding progress. Compounding progress comes from the substrate: shared intent, durable context, and executable checks.
